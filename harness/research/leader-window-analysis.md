# 리더 발화 윈도우 통계 분석 리서치 플랜

작성일: 2026-06-19

## 상태

이 문서는 기능 요구사항이나 구현 계획이 아니라, `채상욱 리더`의 발화 윈도우를 통계적으로 관찰하기 위한 연구 계획이다.

- 2026-06-19 현재 초기 앱 기능화는 `후보 표시` 수준으로만 허용한다.
- 앱의 현재 후보 표시는 `타겟 안정`/`타겟 회복`/`타겟 저밀도`/`고전환` 같은 분석 패턴이며, 확정 판정이나 공식 기능명이 아니다.
- 달력 표시, 본문 배너, 필터 조건은 초기 검증용 UI이며 최종 디자인/임계값으로 고정하지 않는다.
- 연구 산출물과 원문 검토 묶음은 `tools/`나 파서를 변경하지 않는다. 앱 기능화는 별도 요구사항/구현 변경으로 추적한다.
- 원문 대화나 발화 내용을 저장소에 남기지 않는다.
- 사람이 라벨링하기 위한 원문 포함 검토 묶음은 `tmp/research/leader-windows/` 아래의 임시 산출물로만 만들 수 있으며, 저장소에 커밋하지 않는다.

## 문제 정의

목표는 하루 전체에서 리더 발화가 몇 퍼센트였는지를 보는 것이 아니다. 대화 흐름 속에서 리더의 발화 윈도우가 언제 열리고, 얼마나 이어지고, 얼마나 순도 높게 유지되며, 주변 참여자가 어떤 방식으로 끼어드는지를 관찰한다.

연구 중 임시 라벨:

- `은사 타임`: 리더 중심, 높은 순도, 긴 설명 구간
- `부흥의 시간`: 다수 참여자, 높은 발화 밀도, 빠른 사용자 전환 구간
- `혼합형`: 리더 주도이지만 방 전체 반응도 큰 구간
- `아님`: 단순 잡담, 짧은 반응, 노이즈

이 라벨은 연구용이며, 앱에 노출할 명칭이나 최종 분류 체계가 아니다.

## 입력과 산출물

입력:

- 샘플 디렉토리의 유효 대화 TXT/CSV
- 기존 `assets/scripts/chat-core.js` 파서의 `rawMessages`
- 기본 필터 대상 사용자: `채상욱 리더`

분석 기준:

- 표시용 병합 메시지가 아니라 원본 발화 단위인 `rawMessages`를 사용한다.
- 날짜별로 나눈 뒤, 각 날짜 안에서 발화 윈도우를 검출한다.
- 같은 날짜 안에서 리더 발화 간격이 `N분 이하`로 이어지면 같은 윈도우로 묶는다.
- 중간에 다른 사용자가 말해도 윈도우를 끊지 않고, 끼어듦 관련 피처로 기록한다.

산출물:

- 일별 요약 CSV/JSON
- 윈도우 후보 CSV/JSON
- 기본 분석 CSV/JSON은 원문 없는 수치 피처만 포함
- 라벨링 검토용 Markdown/JSON은 원문을 시간대별/발화자별로 묶어 포함할 수 있으나, `tmp/` 아래에만 둔다.
- 실제 분석 산출물은 `tmp/research/leader-windows/` 아래에만 둔다.

저장소에 남기는 것은 이 연구 계획과 피처 정의뿐이다.

## 1차 파라미터

초기 탐색 파라미터:

- `maxLeaderGapMin`: 3, 5, 8, 10
- `minLeaderMessages`: 3, 5, 8
- `contextMin`: 5, 10

기본 시작값:

- `maxLeaderGapMin = 5`
- `minLeaderMessages = 3`
- `contextMin = 10`

이 값은 기능 사양이 아니라, 샘플 데이터에서 분포를 보기 위한 첫 실험값이다.

## 윈도우 피처

각 리더 발화 윈도우마다 아래 피처를 산출한다.

- 식별자: 날짜, 윈도우 순번
- 시간: 시작 시각, 종료 시각, 지속 시간
- 규모: 전체 발화 수, 리더 발화 수, 비리더 발화 수
- 참여: 전체 참여자 수, 비리더 참여자 수
- 순도: 리더 발화 비율, 리더 글자수 비율
- 밀도: 분당 전체 발화 수, 분당 리더 발화 수, 분당 리더 글자수
- 간격: 리더 발화 간격 평균, 중앙값, P90, 최대값
- 연속성: 최장 리더 연속 발화 수
- 끼어듦: 끼어든 발화 수, 끼어든 사람 수, 최대 끼어듦 burst
- 전환: 사용자 전환 수, 사용자 전환율
- 전후 반응: 윈도우 전후 5분/10분의 전체 발화량, 비리더 발화량, 참여자 수

원문 내용, 발화 텍스트, 검색 키워드, 사용자별 상세 문맥은 기본 수치 산출물에 포함하지 않는다. 다만 사람이 후보를 라벨링해야 하므로, 별도의 로컬 검토 묶음에는 후보 윈도우 전후 문맥과 윈도우 내부 발화를 묶어서 보여줄 수 있다. 이 검토 묶음은 임시 분석 자료이며 repo 산출물이 아니다.

## 일별 피처

각 날짜마다 아래 피처를 산출한다.

- 전체 발화 수
- 리더 발화 수
- 전체 참여자 수
- 리더 윈도우 개수
- 총 리더 윈도우 지속 시간
- 평균 윈도우 지속 시간
- 평균 윈도우 순도
- 가장 강한 리더 중심 윈도우 점수 후보
- 가장 강한 집단 반응 윈도우 점수 후보
- 고순도 리더 윈도우 수
- 고밀도 집단 반응 윈도우 수

하루 단위 피처는 날짜를 요약하기 위한 보조 지표일 뿐이며, 윈도우 검출을 대체하지 않는다.

## 분석 절차

1. 샘플 디렉토리를 기존 파서로 읽고 `rawMessages`를 확보한다.
2. 날짜별로 원본 발화 스트림을 나눈다.
3. 여러 파라미터 조합으로 리더 발화 윈도우 후보를 생성한다.
4. 각 윈도우 후보의 수치 피처를 산출한다.
5. 상위 후보만 보지 않고 날짜별 분포와 반복 패턴을 함께 본다.
6. 최소 20개 이상의 윈도우 후보를 사람이 라벨링한다.
7. 라벨 결과를 보고 피처 중요도, 점수식, 임계값 후보를 조정한다.
8. 최소 2회 이상 반복 분석한 뒤에만 앱 기능화 여부를 판단한다.

## 라벨링 기준 초안

### 리뷰 카테고리 기록

2026-06-19 EDA 리뷰 묶음에서는 후보를 아래 네 카테고리로 나눠 사람이 검토한다. 이 구분은 최종 기능 라벨이 아니라, 샘플을 편향 없이 보기 위한 리뷰용 층화 기준이다.

- `A. strict/balanced에서도 유지되는 타겟 발화권`: 엄격한 세그먼트 조건에서도 같은 시간대가 상당 부분 유지되는 후보. 현재 패스에서 가장 깨끗한 타겟 발화권 유지 사례로 본다.
- `B. permissive에서만 길게 이어지는 타겟 발화권`: 짧은 끼어듦과 넓은 타겟 복귀 간격을 허용해야 하나의 긴 구간으로 보이는 후보. 세그먼트 경계와 파라미터 조정에 중요하며, A보다 자동으로 강한 후보라고 보지 않는다.
- `C. 비타겟 끼어듦이 거의 없는 타겟 발화권`: 순도는 높지만 밀도가 낮을 수 있는 후보. 지속 시간만으로 강한 후보로 판단하지 않고, 타겟 발화 수, 글자수, 분당 밀도 같은 guardrail을 함께 본다.
- `D. 방 전체가 촘촘하게 움직이는 고전환 구간`: 타겟 독주가 아니라 다수 참여자, 높은 발화 밀도, 높은 사용자 전환율을 보이는 대비군. 타겟 발화권 유지와 별도 축으로 유지한다.

현재 해석:

- A/B/C는 타겟 발화권 소유와 복귀를 보는 축이다.
- D는 집단 활동성/전환 밀도를 보는 별도 축이다.
- C는 사용자의 1차 리뷰상 “길이는 있으나 밀도는 낮은” 사례가 섞일 수 있으므로, 향후 점수식에서 지속 시간과 밀도를 분리해야 한다.
- 카테고리와 강도는 다르므로, 라벨링 시 `유형`과 `강도`를 분리해 기록한다.

`은사 타임` 후보:

- 리더 발화 비율과 리더 글자수 비율이 높다.
- 리더 발화 간격이 짧고 지속 시간이 충분하다.
- 끼어듦은 있더라도 짧은 추임새 수준이다.
- 최장 리더 연속 발화 수가 길다.

`부흥의 시간` 후보:

- 전체 발화 밀도가 높다.
- 참여자 수가 많다.
- 사용자 전환율이 높다.
- 리더도 존재하지만 독점하지 않는다.
- 윈도우 전후 비리더 반응량이 크다.

`혼합형` 후보:

- 리더 발화 비율이 높으면서도 참여자 수와 사용자 전환율이 함께 높다.
- 리더 주도 설명이 방 전체 반응과 섞여 있다.

`아님` 후보:

- 짧거나 발화 수가 적다.
- 리더 발화가 드문드문 흩어져 있다.
- 단순 잡담 또는 짧은 반응으로 보인다.

## 검증 기준

연구 단계의 성공 기준:

- 같은 샘플과 같은 파라미터로 실행하면 동일한 윈도우 후보가 나온다.
- 기본 윈도우 후보 표에는 원문 발화 내용이 없다.
- 원문 포함 검토 묶음은 `tmp/` 아래에만 존재하며 커밋 대상이 아니다.
- 최소 20개 이상의 후보를 사람이 라벨링할 수 있다.
- `은사 타임`과 `부흥의 시간`을 하나의 점수식으로 섞지 않고, 별도 피처 축으로 비교한다.
- 분석 결과를 근거로 기능화 여부, 명칭, UI 표현을 나중에 별도로 결정할 수 있다.

## 기능화 확대 보류 기준

아래가 충족되기 전까지 후보 표시를 넘어선 확정 판정, 자동 필터, 공식 명칭, 강한 배너 연출로 확대하지 않는다.

- 최소 2회 이상의 파라미터 조정 실험이 끝났다.
- 사람이 라벨링한 후보군이 충분히 모였다.
- `은사 타임`, `부흥의 시간`, `혼합형`, `아님` 사이의 구분 기준이 설명 가능하다.
- 오탐/미탐 사례가 문서화되었다.
- 사용자에게 보여줄 명칭과 UI 위치가 별도 계획으로 합의되었다.
